# Dev flow conventions

These rules are distilled from trawler-incremental, monhun-ardu, and
CreatureGathererFX. They are about the repo, not a particular tool. Canonical
hardware and resource facts live in `docs/platform.md`.

## Inner loop vs full gate

- Host: `make test`; tooling: `make test-tools`; docs: `make docs-check`.
- Story text: `make editor`, then open
  `http://localhost:8000/docs/story-editor.html`.
- Developer map inspection: `make debug` builds `DEBUG=1` and launches Ardens.
  In that image, A on the chart toggles world collision off/on, and holding A
  in flight moves the boat at 3x position speed while air, currents, docking
  and the voyage clock keep production pacing. The release build and output
  directories are unchanged.
- Ardens save continuity: `make save-migrate SAVE=/path/absim_<hash>.save`
  copies an existing save under the current image's key. Add `DEBUG=1` to
  migrate to the debug image. The source save and its payload are untouched;
  the new key name is printed. The schema-7 save layout is unchanged.
- One device suite while iterating: `make fxtest FXTEST_ONLY=test_boot`.
- Full device gate: `make fxtest` compiles the 15 default fixed-build suites
  and requires an exact bare `P` marker from each. It excludes the longer
  `test_flight` probe and the emulator-only runtime-page suite.
  `fxtest-save-chain`, `fxtest-save-runtime-page` and `fxtest-flight` are
  explicit targets. If `ARDENS` is unset or not executable, the run reports
  SKIPPED; an Ardens without `captureserial` is BLOCKED, never a pass.
- Full gate before a commit: `make gen-check`, `make test`, `make test-tools`,
  `make docs-check`, `make fxtest`, `make fxtest-save-chain`,
  `make fxtest-save-runtime-page`, `make fxtest-flight`, `make size`,
  `make mini`.
- Camera/render changes additionally require `make fxtest-flight`: this longer
  probe measures complete production flight frames with active ATMlib2FX synth
  music, including fractional scrolling, cold caches and discovery notices.
  Render-only averages do not establish that a complete frame meets its
  deadline.

## Generated artifacts

- `make gen` is the only shipping generation entry. The former sampled-audio
  reference pipeline (`make gen-audio`, reference PCM/ADPCM evidence) was
  retired and removed.
- `make gen-check` snapshots the generated set, re-runs `gen`, and fails on any
  byte change. Run `make gen` once before using it the first time.
- `fxdata/fxdata.txt` is an ordered flash layout. Declaration order is ABI:
  append new entries; never reorder or remove one after it has shipped.
- Stage generated sets together after a regen. Never commit a half-generated
  set.
- Story prose, scene order and image-row names live in `story/scenes.json`;
  mission copy lives in `story/missions.json`; berth hints live in
  `story/dock_hints.json`. The canonical Piskel artwork sheet is `story/art.png`.
  See `story/README.md`. Use `docs/story-editor.html` for text-only edits, then
  run `make gen`; do not add shipping card copy to the HTML preview or generator.
  Preview with `docs/story-sketchbook.html`.
- Tests read generated symbolic constants, never literal record indices.

## Release runtime and uploader entry

- The release sketch `sub-hauler.ino` always places `ARDUBOY_NO_USB` before
  `setup()` and delegates operations to `src/app.hpp`. There is no runtime-USB
  production variant.
- The device suites are separate fixed `.ino` sketches that retain USB so
  Ardens can capture the serial marker.
- There is no in-game loader row. The library's startup `DOWN` check is the
  bootloader entry when the running image cannot be reset by an uploader.
- Build outputs are `build/arduino` / `dist/fx` and
  `build/arduino-mini` / `dist/mini`; the host binary is `build/tests/host`.

## Budget-first for flash/SRAM work

- LTO makes per-symbol size math meaningless. Measure the whole image with
  `make size` (`.text` + `.data` for flash; `.data` + `.bss` for static SRAM)
  and compare against the limits in `docs/platform.md`.
- Spike before a change that can touch flash or RAM; report the whole-image
  delta. Split "implement" from "make it fit".
- Keep a stack reserve. Static free bytes alone do not prove stack fit.
- Art is authored native 1-bit and baked into the native terrain/FX sections;
  treat new art and each new section as a measured cart/flash cost, not as a
  disposable placeholder.

## Device-test RAM budget

- Device suites compile with `--optimize-for-debug`, which keeps globals
  visible and often larger. Keep large constant tables in PROGMEM.
- If a suite corrupts earlier cases, inspect `.data`/`.bss` before suspecting
  render drift.

## Startup introduction

The fixed build shows the Snailware and game splash before the title. Art lives
in the appended FX startup section and is generated by `make gen`. The
title/menu music cue starts with the first splash and keeps playing into the
title; voyage time begins afterward. Any button skips; release is consumed
before title input. See
[startup-splashes.md](startup-splashes.md) for source attribution and measurements.

## Rendering and FX

- The OLED and cart share SPI. Cart reads happen in update/render, never during
  an OLED transaction. The canonical display contract is in `docs/platform.md`.
- Static menu screens compose once per input edge and skip the OLED
  transaction while idle. The native station board uses a 7 px row pitch and a
  raw `fillRect` selection bar; every label is a baked 128x8 plus-mask FX stamp
  (`text::stamp`/`stampFrame`), so no font draw or per-glyph cart read runs at
  runtime. The generated station/shop frames stay archival cart ABI only; no
  screen selects them.
- Greyscale is not a shipping path: normal builds are native 1-bit, and
  `FRAME(x)` is the logical frame (`x`). `Blit::draw` reads headerless
  page-major plus-mask bytes.
- Generated sprite blobs start with a two-byte `(width, height)` header.
  `SpritesU::drawPlusMaskFX` owns that header; `Blit::draw` expects the caller
  to skip it.

## Save data

- The fixed build calls `FX::begin(FX_DATA_PAGE, FX_SAVE_PAGE)`; the generated
  image ends with a 4 KiB `savesection`.
- Voyage checkpoints live in one 4 KiB cart erase block with a single slot. A
  save erases the block, programs two 256 B pages and writes the commit byte
  last. A power interruption may lose the checkpoint; a torn record is rejected
  and the title offers a clean New Voyage. Music is paused around the
  synchronous erase/page transaction; no read or write belongs in the per-frame
  path.
- The standalone EEPROM chart writer is retired; schema 7 voyage checkpoints
  are the only save path.
- `make fxtest-save-chain` runs the exact production
  `updateStation()`→`requestSave()`→`saveVoyageNow()` path with the real sketch
  and ATMlib2FX synth music; it is emulator-only and performs real cart writes.
- `make fxtest-save-runtime-page` proves page writes use runtime
  `FX::programSavePage`, not the compile-time constant. It points the save page
  at the 4 KiB data tail, so it is emulator-only and must never run on hardware.
- Re-run `make gen` after changing `savesection`; `make gen-check` compares the
  packed image, save partition and header.
