# Startup splashes — 2026-10-28

Normal voyage builds show the original Snailware logo and then a Sub-hauler
title scene before the existing title menu. The logo lasts 60 × 16 ms (about
1 s); the title splash lasts 150 × 16 ms (about 2.4 s). The complete
introduction measures 3,417 ms including presentation and release debounce.
Any held button skips the introduction; waiting for release prevents that
input from selecting NEW VOYAGE or CONTINUE. The final timeout also waits
for release. Music and voyage time start after the introduction. Developer and
campaign/save-off profiles keep their existing startup.

The [preview](../build/splash-preview.png) is generated by `make gen`. The
original 64×64 [Snailware source](../images/splash/source/README.md) is retained
unchanged with its upstream MIT license and verified blob SHA. SNAIL / WARE
placement follows AllYourArdu. The game screen uses the existing HAULER art
and font with a baked underwater scene. Two opaque 128×64 frames cost 2,050 B
of FX payload and no program-memory bitmap storage.

The camera calculation is algebraically identical: adding integer pixels
after rounding the fractional difference avoids the AVR's former 32-bit
multiply/shift. Cue table list initialization rejects values that cannot fit
16 bits. Title panels preserve their exact pixels through the already-used
opaque reader. Savings total 180 B; startup costs 100 B; the final image has
**80 B hardware flash headroom**, 38 B static headroom and 898 B static free.
Mini matches the full image. Music-off is 24,940 / 1,458 B; streaming comparison
27,122 / 1,618 B. Lean/core/min measure 14,874/12,742/6,778 B flash and
1,417/1,159/1,115 B static.

All previous 2,075,502 payload bytes remain identical. New payload/image are
2,077,552 / 2,081,792 B, leaving 15,360 B below 2 MiB; save schema/page/behavior
are unchanged. Only append declarations before the save-section marker.
