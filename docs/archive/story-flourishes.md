## Trigger and replay contract

`story_view::cardForNewMilestone(before, after)` compares the saved campaign
mask across the docking step:

| New milestone | Card |
| --- | --- |
| `kMilestoneFirst` | BENTHOS |
| `kMilestonePump` | PUMP REFUGE |
| `kMilestoneLift` | CORMORANT |
| `kMilestoneBeacon` | DEEP ANCHOR |
| `kMilestoneHome` | existing ending thanks card |

- Delivery resolves inside `station::stepFlight`, then the complete post-delivery
  checkpoint is written **before** any story card is shown.
- If the checkpoint fails, the SAVE FAILED screen wins. RETRY after a successful
  write, or CONTINUE UNSAVED, resumes the pending card before the station board.
- If HOME becomes pending, the existing ending path takes precedence; the
  homecoming line is the second existing ending card.
- A fresh **A or B** edge advances a card. A held chord does not.
- Advancing returns to the station board. The milestone is already saved, so the
  card itself has no write.
- Cards do not replay after reload or after returning to the station. Only one
  small bss byte tracks the pending card; it is not serialized and is cleared by
  `resetRun()`.
- The ending remains replayable from Tidewall WORK (`VIEW ENDING`), including
  the TIDEWALL homecoming card.

No existing clue, objective, save, ending-card order, music or input ordering was
removed or reordered.
